{{template "i-film"}}

Converting and transcoding

{{- if not .Data.CanConvert}}

There is no ffmpeg and ffprobe to run, so films and episodes go to boxes as they are. Install ffmpeg on the server, then restart Overscan.

{{- else if not .Data.CanTranscode}}

This server's ffmpeg has no libx264, so it can convert sound but not transcode video. Install an ffmpeg built with it, then restart Overscan.

{{- else if not .Data.ToneMap}}

This server's ffmpeg has no zscale filter, so HDR video it transcodes comes out washed out.

{{- else}}

ffmpeg can convert sound, transcode with libx264, and map HDR to SDR

{{- end}}

{{if .Data.ConvertSound}}A film or an episode whose sound or file a box cannot play, such as DTS, goes through ffmpeg, which copies its picture and converts its sound to Dolby Digital. It takes little of the server.{{else}}Off: films and episodes whose sound or file a box cannot play go to it as they are, and it may play them without sound, or not at all.{{end}}

{{if .Data.Transcodes}}Films and episodes whose video a box cannot play, such as 4K or AV1, come to it as 1080p H.264 that this server's ffmpeg makes as they play, {{.Data.Transcodes}} at a time. Another box that asks then is told the server is busy.{{else}}Off: films and episodes whose video a box cannot play, such as 4K or AV1, go to it as they are, and it may not show them.{{end}}

{{if .Data.ServerTranscodes}}A Jellyfin server transcodes its own films and episodes whose video a box cannot play, on its own processor, whatever this server is set to do.{{else}}Off: Jellyfin's films and episodes whose video a box cannot play go to it as they are.{{end}}

Transcoding needs a fast processor, above all for 4K: when ffmpeg cannot keep up, the box stops to wait, and the server's log says so. Stalker clients always get films as they are.

Shared tuner

{{if .Data.SharedTuner}}On{{else}}Off{{end}}

{{if .Data.SharedTuner}}Boxes, Stalker clients and recordings that play the same channel share one connection to its source, which counts once against the source's limit. A box can record the channel it plays on a source that allows one stream.{{else}}Off: each screen that plays a channel has a connection of its own to the source, and counts against the source's limit.{{end}}

Whether your provider lets several screens share one connection is between you and your provider: check its terms before you turn this on. A shared channel's last seconds go in the data directory while it plays. Channels whose address is HLS, and radio stations, keep a connection for each screen.

{{template "i-backup"}}

Backups

Overscan keeps everything in one database. As the user that runs Overscan, this writes a copy of it to the backups folder in the data directory, even while the server runs:

overscan backup

On an installation from install.sh, that is runuser -u overscan -- overscan backup. Keep a copy of the key file apart from the backups: whoever has both can read the sources' logins. The backup guide in Overscan's docs says how to restore.
